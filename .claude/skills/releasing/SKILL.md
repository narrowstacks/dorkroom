# Releasing Dorkroom

## Versioning

- **CalVer** (`YYYY.MM.DD`) — all `package.json` versions use the date changes are pushed to main.
- When pushing to main, update the `package.json` version of each app you changed to the current date (web: root; iOS: `apps/mobile`, see "iOS release flow" below). The apps are independent.
- The README version badge (and the React/Tailwind/TypeScript badges) are auto-synced from
  `package.json` by the `Sync README Badges` workflow — **do not hand-edit them**.
- The homepage screenshot in the README is regenerated by the `Homepage Screenshot` workflow, but only when a push opts in: the PR carries the `home page` label or a commit message contains `[screenshot]` (or run it manually via workflow_dispatch).

## Changelog

Add a new entry summarizing what changed, using [Keep a Changelog](https://keepachangelog.com/)
format, to the changelog for the app you touched:

| App     | Changelog                | Version source              |
| ------- | ------------------------ | --------------------------- |
| Web app | root `CHANGELOG.md`      | root `package.json`         |
| iOS app | `apps/mobile/CHANGELOG.md` | `apps/mobile/package.json` |

The two apps version **independently**.

## iOS release flow

- The iOS app has **one** version source: `apps/mobile/package.json`.
  `apps/mobile/app.config.ts` copies it into the Expo config (Settings and
  `CFBundleShortVersionString`), so `app.json` carries no `version`. Never add
  one back.
- To release: bump `apps/mobile/package.json` to the push date, move the
  `[Unreleased]` section of `apps/mobile/CHANGELOG.md` under a new
  `[YYYY.MM.DD]` heading, then build and submit (see the TestFlight section of
  `apps/mobile/README.md`).
- The build number is owned by EAS (`appVersionSource: remote`, `autoIncrement`
  on the production profile). Do not edit it in the repo.
- The web version bump on push to main (above) does **not** touch
  `apps/mobile/package.json`; only bump it when the iOS app changed.
- Never apply the `eas-build` label unless a build is intended.
